\chapter{Préambule}
Le cahier de recette s’inscrit dans le cadre du projet de développement d’un système de recommandation de films. Ce document définit l'ensemble des procédures de tests et de validation permettant de vérifier que l'application livrée est conforme aux exigences spécifiées dans le cahier des charges. À l'issue de ces tests, il permettra d'officialiser la validation du produit final.

\section{Objectifs et méthodes}
L’objectif principal de ce cahier de recette est de vérifier que l’application respecte les spécifications fonctionnelles et techniques établies lors de la phase de conception. Il s’agit de s’assurer que chaque fonctionnalité obligatoire définie dans le cahier des charges (FR-01 à FR-09) est opérationnelle, accessible et conforme.

La méthode utilisée repose sur des tests manuels réalisés via l’interface web, accessible depuis un navigateur standard. Chaque scénario précise les données en entrée, les résultats attendus ainsi que les critères de validation permettant de déterminer la conformité ou la non-conformité de la fonctionnalité testée. Un résultat est considéré comme valide lorsque le comportement observé correspond exactement au comportement attendu décrit dans le scénario. Toute anomalie détectée devra être signalée et analysée avant validation définitive.

\chapter{Concepts de base}
Cette section présente les notions essentielles nécessaires à la compréhension des tests et de la logique du système de recommandation de films. Pour la suite du projet, on considère qu'un film noté par un utilisateur correspond à un film déjà vu par celui-ci.
\section{Système de recommandation}
\label{SR1}
Un système de recommandation est un ensemble de méthodes permettant de suggérer des films à un utilisateur en fonction de données existantes. Dans ce projet, l'utilisateur fournit initialement ses notes et préférences via un formulaire lors de la création de son compte, et ces informations sont utilisées pour générer ses recommandations personnalisées.

\section{Jeu de données}
\label{JD1}
Ensemble structuré d'informations exploité par le système. Dans ce projet, il s'agit d'un fichier contenant des films ainsi que les évaluations associées.

\section{Données utilisateurs}
\label{DU1}
Les données exploitées pour générer les recommandations incluent : 
\begin{itemize}
    \item L'historique de visionnage.
    \item Les notes attribuées aux films.
\end{itemize}
Ces informations sont essentielles pour vérifier la pertinence et la cohérence des recommandations lors des tests.

\section{Algorithme de recommandation}
\label{ADR1}
Méthode de calcul permettant de générer des suggestions de films. Le modèle repose sur des algorithmes de calcul de similarité entre films.
Les tests de recette vérifieront que : 
\begin{itemize}
    \item Les calculs sont cohérents.
    \item Les recommandations sont pertinentes.
    \item Les résultats sont reproductibles.
\end{itemize}

\section{Interface web}
\label{IW1}
Interface accessible via un navigateur permettant à l'utilisateur d'interagir avec le système.
Le système inclut une interface permettant : 
\begin{itemize}
    \item De consulter les recommandations de films générées.
    \item De noter des œuvres.
    \item De rechercher des films.
\end{itemize}
Les tests vérifieront la cohérence entre les actions de l'utilisateur et les résultats affichés.

\section{SC-01 - Création d'un compte utilisateur}
\label{CU1}
\subsection*{Description}
Ce scénario vérifie qu’un utilisateur peut créer un compte en saisissant des informations valides dans le formulaire d’inscription.
Le test assure que les données saisies sont correctement transmises au système, vérifiées, puis enregistrées si elles respectent les règles définies (champs obligatoires remplis, format d’email valide, mot de passe conforme...).

\textbf{Environnement du test :}\\
Application Web fonctionnelle accessible via un navigateur.

\subsection*{Contraintes}
\begin{itemize}
    \item  Le formulaire d’inscription doit être accessible.
    \item Base de données utilisateurs opérationnel.
    \item L’email et le nom de l'utilisateur utilisés pour le test ne doivent pas être enregistrés dans le système.
    \item Le compte a été validé par les administrateurs.
\end{itemize}

\subsection*{Dépendances}
\begin{itemize}
    \item Accès à la page d’inscription.
\end{itemize}
  
\subsection*{Procédure de test}
\subsubsection{Données en entrée :}
Création de compte :
\begin{itemize}
    \item Nom d’utilisateur : NomNouvelUtilisateur.
    \item Email : nouvelUtilisateur@example.com .
    \item Mot de passe : NouveauMotDePasse123 .
\end{itemize}
\subsubsection{Résultats attendus :}
Le système crée le compte utilisateur, affiche un message de confirmation et redirige l’utilisateur vers son espace personnel ou la page de connexion.

\subsubsection{Critères de validation :}
\begin{itemize}
    \item L’accès à la création de compte est possible.
    \item Le compte est créé avec succès.
    \item L’utilisateur peut se connecter avec le nouveau compte créé.
    \item L’accès au système est autorisé.
    \item Aucune anomalie n’est observée.

\end{itemize}

\section{SC-05 - Première recommandation}
\label{Rec1}
\subsection*{Description}
Vérifiez que lors de la première demande de recommandation, le système retourne bien une recommandation basée sur les préférences enregistrées pendant la première connexion au compte utilisateur (voir \ref{Co1}).

\textbf{Environnement de test : }\\
Application web fonctionnelle accessible via un navigateur.

\subsection*{Contraintes}
\begin{itemize}
    \item Backend accessible.
    \item L’utilisateur doit avoir fait une demande de création de compte et rempli le formulaire.
    \item Le compte doit avoir été validé par les administrateurs.
    \item L’utilisateur doit avoir rempli le questionnaire de préférences.
    \item Les premières préférences de l’utilisateur doivent être enregistrées.
\end{itemize}

\subsection*{Dépendances}
\begin{itemize}
    \item Fonctionnalité de création de compte opérationnelle.
    \item Les premières préférences de l’utilisateur ont bien étaient enregistrées.
\end{itemize}

\subsection*{Procédure de test}
\subsubsection{Données en entrée :}
\begin{itemize}
    \item Compte utilisateur valide.
    \item Premières préférences de l’utilisateur.
\end{itemize}
\subsubsection{Résultats attendus :}
En se basant sur les premières préférences de l’utilisateur, le système retourne une liste de films recommandés personnalisées.
\subsubsection{Critères de validation :}
\begin{itemize}
    \item Une liste d’au moins 6 films est retournée.
    \item La liste de film est pertinente, la pertinence sera évaluée par rapport aux mesures de qualités de l’algorithme de recommandation.
\end{itemize}

\section{SC-06 - Renouvellement des recommandations}
\label{Rec2}
\subsection*{Description}
Vérifier que le système ne recommande pas de films déjà notés par l'utilisateur et que les listes de recommandations ne sont pas identiques entre deux exécutions successives lorsque l'utilisateur a fourni des informations supplémentaires (nouvelles notes).\\
L'utilisateur dispose déjà d'un profil et a renseigné des données initiales. Il ajoute ensuite de nouvelles évaluations via l'interface. Le système doit recalculer les recommandations en tenant compte de ces informations.

\textbf{Environnement de test : }\\
Application web déployée, accessible via un navigateur standard, avec un jeu de données chargé.


\subsection*{Contraintes}
\begin{itemize}
    \item L'utilisateur doit être identifié pour que le système puisse associer les données à son profil. 
    \item Le jeu de données doit contenir suffisamment de films pour permettre le renouvellement des suggestions.
    \item Un historique de notes initiales doit exister. 
\end{itemize}

\subsection*{Dépendances}
\begin{itemize}
    \item Création préalable d'un compte utilisateur.
    \item Fonctionnalité de notation opérationnelle.
    \item Génération initiale de recommandations disponibles.
\end{itemize}

\subsection*{Procédure de test}
\subsubsection{Données en entrée :}
\begin{itemize}
    \item Profil utilisateur existant.
    \item Films notés initialement.
    \item Nouvelles notes attribuées à plusieurs films.
\end{itemize}
\subsubsection{Résultats attendus :}
Le test est validé si la liste est actualisée, pertinente et exempte de films déjà visionnés.

\subsubsection{Critères de validation :}
\begin{itemize}
    \item La nouvelle liste ne contient pas de films déjà notés par l'utilisateur.
    \item La liste diffère de la précédente (au moins partiellement).
    \item Les recommandations restent cohérentes avec les préférences de l'utilisateur.
\end{itemize}

\section{SC-07 - Remise à zéro (RAZ)}
\label{DU2}
\subsection*{Description}
Vérifier que dans le cas où l’utilisateur à mal remplis ses préférences lors de la première connexion, il est possible de réinitialiser les informations entrées et de reprendre depuis le début pour les recommandations.\\ 
Le système doit alors supprimer les données de préférences déjà enregistrées et supprimer ou invalider les recommandations qui avaient été générées à partir des mauvaises préférences.

\textbf{Environnement de test : }\\
Application web fonctionnelle accessible via un navigateur.

\subsection*{Contraintes}
\begin{itemize}
    \item Backend accessible.
    \item L’utilisateur doit être connecté à son compte.
    \item Des préférences  doivent déjà exister sur son profil.
\end{itemize}

\subsection*{Dépendances}
\begin{itemize}
    \item Existence d'un profil utilisateur enregistré.
    \item Fonctionnalité d'authentification opérationnelle.
    \item Fonctionnalité de gestion des préférences opérationnelle.
    \item Fonctionnalité de recommandation fonctionnelle.
\end{itemize}

\subsection*{Procédure de test}
\subsubsection{Données en entrée :}
\begin{itemize}
    \item Compte utilisateur valide.
    \item Préférences déjà enregistrées.
    \item Action de réinitialisation déclenchée par l’utilisateur.
\end{itemize}
\subsubsection{Résultats attendus :}
Les anciennes préférences sont supprimées et le système redirige l'utilisateur vers le formulaire rempli lors de la première connexion.
\subsubsection{Critères de validation :}
\begin{itemize}
    \item Les anciennes préférences sont supprimées.
    \item Les recommandations personnalisées disparaissent.
    \item L’utilisateur est redirigé vers une page demandant de rentrer de nouvelles préférences.
    \item Le système propose de nouvelles recommandations à partir des nouvelles préférences.
\end{itemize}

\section{SC-09 - Notation d'un film}
\label{Fi2}
\subsection*{Description}
Vérifier qu’un utilisateur peut attribuer une note à un film et que cette note est correctement enregistrée par le système, puis prise en compte dans le calcul des recommandations.

\textbf{Environnement de test :}\\
Application web fonctionnelle accessible via un navigateur.
\subsection*{Contraintes}
\begin{itemize}
    \item L’utilisateur doit être authentifié.
    \item Fonctionnalité d’authentification opérationnelle.
    \item Accès à la fiche d’un film.
\end{itemize}

\subsection*{Dépendances }
\begin{itemize}
    \item Existence d’un profil utilisateur enregistré.
    \item Fonctionnalité d’authentification opérationnelle.
    \item Accès à la fiche d’un film.
\end{itemize}

\subsection*{Procédure de test}
\subsubsection{Données en entrée :}
\begin{itemize}
    \item Compte utilisateur valide.
    \item Film existant dans le catalogue.
    \item Valeur de note à attribuer.
\end{itemize}

\subsubsection{Résultats attendus :}
Le test est validé si la note saisie est correctement sauvegardée, affichée ultérieurement et prise en compte par le système sans erreur.

    \item La note est associée au bon utilisateur.
    \item Les recommandations sont mises à jour en fonction de cette nouvelle information.
\end{itemize}

\chapter*{Glossaire}
\addcontentsline{toc}{chapter}{Glossaire}
\begin{itemize}
    \item \underline{Algorithme :} Un algorithme peut s’apparenter à une recette de cuisine, il s’agit d’un ensemble fini d’instructions détaillées permettant de résoudre un problème ou effectuer une tâche.\\
    \underline{NB :} Dans notre cas, nous utiliserons un algorithme de recommandation, qui permet de proposer des contenus pertinents à un utilisateur.
    \item \underline{Application web :} Une application Web est un logiciel qui s'exécute dans votre navigateur Web.
    \item \underline{Backend :} Le backend est la partie invisible, qui gère le fonctionnement interne du produit (par exemple : les données).
    \item \underline{Base de données :} Une base de données est un ensemble d'informations organisé de manière à être facilement accessible, géré et mis à jour.
    \item \underline{Bug :} Un bug est un défaut de conception d'un programme informatique à l'origine d'un dysfonctionnement.
    \item \underline{Cloud :} Le cloud est un réseau mondial de serveurs distants conçu pour stocker et traiter des données pour d'autres appareils et ordinateurs.
    \item \underline{Framework :} Un framework est une structure prête à être utilisée pour développer un logiciel, il contient des outils et des bibliothèques.
    \item \underline{Frontend :} Le frontend est la partie visible du site web, c'est ce avec quoi l'utilisateur interagit directement.
    \item \underline{GitHub :} GitHub est une plateforme basée sur le cloud où l'on peut stocker, partager et travailler avec d'autres pour écrire du code.
    \item \underline{Interface web :} Une interface web est une interface  à laquelle on accède et qui s'affiche grâce à un navigateur web, qui permet un dialogue entre l'utilisateur et le système.
    \item \underline{Jeu de données :} Un jeu de données est un ensemble structuré de données. 
    \item \underline{Navigateur :} Un navigateur est une application qui vous permet de naviguer sur les sites web d'internet.
    \item \underline{Site web :} Un site web est un ensemble de pages web qui peuvent être consultées en suivant des hyperliens à l'intérieur du site.
    \item \underline{Subversion (SVN) :} SVN est un gestionnaire de version de code source.
    \item \underline{Système de recommandation :} Un système de recommandation est un système qui permet de proposer des contenus ou des produits en fonction de ses préférences.
    \item \underline{Test automatisé :} Un test automatisé est un processus de vérification et de validation des fonctionnalités d'un logiciel, d'une application ou d'un système informatique, qui est effectué automatiquement à l'aide d'outils spécialisés.
\end{itemize}
